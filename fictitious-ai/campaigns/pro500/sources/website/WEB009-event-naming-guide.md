# Name events for the question they need to answer

An event name is a small piece of analytical language. Make it useful to a person who did not implement the interaction.

## Describe an observable action

Prefer a description of what happened over a conclusion about the user's motivation. A completed action is an observation. An assertion that the user found value is an interpretation that needs separate support.

## Write down the trigger

Document when an event is recorded, what it represents, and any important limitation. Two people should be able to read the definition and explain the same behavior.

## Change definitions deliberately

If an event's meaning changes, record the change before comparing periods. A movement in a chart can reflect a measurement change as well as a behavior change.

Before your next analysis, ask a colleague to read one event definition and explain what it does not tell them. That conversation is often a useful first check.
